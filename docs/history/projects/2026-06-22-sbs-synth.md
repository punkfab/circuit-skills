## Goal

Dan wanted a single-PCB music synthesizer with these constraints:
- Cheap JLCPCB turnkey production with **no post-assembly** and no calibration.
- Keys are capacitive copper pads on the PCB.
- Only JLCPCB-stocked chips. Dan would hand-solder any custom parts until volume justified stocking them.
- About **$50 unit cost**.
- Many variants: hybrid analog (digital oscillators feeding an LM13700 OTA filter) and DSP/FM.

His main requirement was to make **routing "as automated as possible"**. His earlier RP2354A board, `2040-artnode`, "never got done" because he got stuck routing it with Freerouting. Later in the session he stated the guiding principle himself: **"every autorouter is immature"**. He then asked for that experience to be turned into a reusable PCB-layout skill.

## Problems and fixes

1. **Planned touch IC and MCU were too thinly stocked at JLCPCB**
   - **Symptom:** `tsci search --jlcpcb` reported BS8116A-3 (C89208) stock **25** and RP2354A (C41378174) stock **184**. Alternatives were also thin: CAP1188 65, CAP1296 10; TTP229, IQS316 and AT42QT1110 were not stocked.
   - **Root cause:** supply availability.
   - **Tried:** searched alternatives.
   - **Resolution:** fixed.
     - **MPR121QR2 (C91322, 408 stock)**: 12 channels, 4 I²C addresses, so up to 48 keys.
     - **RP2350A (C42411118, 7,892) + W25Q16JVSNIQ (C2456211, 25,612)** instead of the in-package-flash RP2354A.
     - PT8211-S C5260468 (1,597) and LM13700MX C174050 (7,419) were already fine.
   - **Where:** `index.circuit.tsx` / `imports/`; the "stock-check first" step in `PCB_WORKFLOW.md` §1 and the pcb-layout skill.

2. **`tsci --help`, `tsci check netlist` and `tscircuit-cli --help` print nothing when piped**
   - **Symptom:** 0-byte output files, exit 0.
   - **Root cause:** the `tsci` output is TTY-gated. Also, the `tscircuit` package's `tsci` has an `#!/usr/bin/env bun` shebang: `/usr/bin/env: 'bun': No such file or directory`.
   - **Tried:** `npx @tscircuit/cli@latest`, `npm view` to find the bin, the node-based `tscircuit-cli`.
   - **Resolution:** installed bun 1.3.14 (`curl bun.sh/install`), always `export PATH="$HOME/.bun/bin:$PATH"`, and use artifact-writing commands (`tsci build`) with logs redirected to files.
   - **Where:** `PCB_WORKFLOW.md` §0 and §6 Gotchas; pcb-layout Pitfalls.

3. **`tsci build --pcb-png pcb_v1.png` failed**
   - **Symptom:** `Cannot find module '.../pcb_v1.png'`, `circuit_generation_failed`, exit 2.
   - **Root cause:** `--pcb-png` is a boolean, so the positional argument was taken as the input file.
   - **Resolution:** fixed; the correct form is `tsci build <file> --pcb-svgs/--pcb-only`.
   - **Where:** memory `tscircuit-build-gotchas`.

4. **Stale `tsci check netlist` process burning CPU and starving later builds**
   - **Symptom:** PID 375084 was still running long after it was started.
   - **Root cause:** killing the `timeout`/bash wrapper left the `bun` child re-parented and alive.
   - **Tried:** `kill` of the wrapper PIDs (exit 144); the process survived.
   - **Resolution:** `kill -9` the bun PID directly, and later `pgrep -af 'bun .*tsci'` to verify.
   - **Where:** `PCB_WORKFLOW.md` §6 ("Killed `timeout` but build still runs").

5. **`pkill -9 -f 'tsci'` killed its own shell**
   - **Symptom:** the schematic-only build in the same command never ran; `sch.log` was empty; the task "failed with exit code 1".
   - **Root cause:** the pkill pattern matched the invoking shell's own command line, which contains "tsci".
   - **Resolution:** match the exact subcommand or use stored PIDs.
   - **Where:** `PCB_WORKFLOW.md` §6. This is the same family as the pgrep/pkill self-match trap later recorded in other skills (inferred link).

6. **Monolithic board hangs forever at `Dispatch phase complete. Created 24 sub-solvers.`**
   - **Symptom:** observed with routing enabled, with `--routing-disabled`, with `--routing-disabled --pcb-only` and no pour, and with `sequential-trace` + footprints + pour. The last run went **12 min at 100% CPU, EXIT=137 (killed), 0 traces, no circuit.json**. Dan: "It's working pretty hard... I had this experience with freerouter."
   - **Root cause:** never isolated inside tscircuit. Each hypothesis was eliminated in turn:

   - **Where:** `PCB_WORKFLOW.md` §2 "Build in modules (non-negotiable for dense boards)"; pcb-layout "modular subcircuits".

7. **Default autorouter fails even on a 9-part module**
   - **Symptom:** `AutorouterError: AD ran out of iterations (capacity-autorouter@0.0.583)` in `PcbTraceRender "capacity-mesh-autorouting"`. The build still reported "1 passed" and exit 0, but there were **0 `pcb_trace`** elements. The first "routed" audio PNG Claude showed was placement only.

   - **Resolution:** fixed with `autorouter="sequential-trace"`. `auto-cloud`, `freerouting` and effort levels were never tried.
   - **Where:** `PCB_WORKFLOW.md` §3; pcb-layout routing recipe.

8. **`sequential-trace` fatal-errors on footprint-less parts**
   - **Symptom:** `PinHeader "J_I2S" does not have a footprint. Add a footprint prop` (exit 1).
   - **Root cause:** capacity-mesh auto-assigned footprints; sequential-trace requires them explicitly.
   - **Resolution:** fixed with `footprint="pinrow4"`/`"pinrow3"` on headers and `footprint="pushbutton"` on buttons. The audio module then gave **16 traces + 6 vias, 0 unrouted**.
   - **Where:** `PCB_WORKFLOW.md` §3/§6.

9. **Built-in USB-C connector unusable**
   - **Symptoms:**
     - With `--disable-parts-engine`: `Could not find port for selector "USBC.VBUS1"... It has no ports`.

     - Also a warning: `standard="usb_c" but no manufacturerPartNumber`.
   - **Root cause:** `<connector standard="usb_c">` gets its ports from the parts engine and provides no footprint string that sequential-trace accepts.
   - **Resolution:** fixed by importing a real part, **TYPE-C-31-M-12 (C165948, 336,394 stock)**. Pin labels: A5/B5 = CC, A6/B6 = D+, A7/B7 = D−, A4B9/B4A9 = VBUS, A1B12/B1A12 = GND, EH1–4 = shield. The power module then gave 64 traces.

## Decisions and reversals

- **Freerouting needs a Java patch → it doesn't.** Dan's "routed on the planes" symptom was diagnosed as layer config: deactivate the inner layers, route 2-layer, pour afterwards. A patch (auto-deactivating `(type power)` layers) was kept as optional.
- **GUI "uncheck inner layers" advice → withdrawn.** Dan runs `freert` headless. It was replaced by `--skip-nets` plus Python DSN preprocessing to strip In1/In2. This was never implemented, because the next reversal made it moot.
- **Reuse the 2040-artnode SKiDL + pcbnew + freert flow ("don't introduce atopile/tscircuit") → tscircuit**, 2026-06-22 19:14. Reason: artnode died on routing, and tscircuit has integrated routing and AI-native authoring. A "one-module spike first" was proposed, and Dan said full send.
- **4-layer as the default → 2-layer + ground pour for v1.** A cap-sense board doesn't need 4 layers, and 2 layers avoids the plane problem.
- **RP2354A → RP2350A + external flash; BS8116A-3 → MPR121**, both because of JLCPCB stock.
- **Default capacity-mesh router → `sequential-trace`.** Sequential-trace "fails fast" instead of spinning.
- **"Modules are optional, for reuse" → "mandatory for this board in tscircuit".** This followed the 12-minute monolith hang.
- **"MCU module fully routed (47 traces)" → retracted.** It had 16 unrouted. The reliable metric became log grep, then KiCad DRC.
- **"Compose vs separate PCBs" → irrelevant.** Unrouted nets live inside the sections, so per-section placement is the real lever.
- **"tscircuit routes 80%, KiCad finishes 20%" → "tscircuit = schematic + placement generator; KiCad does *all* routing".** This followed the DRC finding of 39 shorts and 35 crossings.
- **Trust tscircuit auto-layout (`pack`/`match-adapt`) → encode placement in code** (`Decap`, edge-aware).
- **Top-side decoupling at pins → bottom-side under the QFN** (11 → 6 unrouted).
- **Repo visibility:** published **private** by default (WIP hardware). Dan chose a "Full move" (GitHub + folder + session dir) over "GitHub only".
